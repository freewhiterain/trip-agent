按时间顺序排号，编号 + 意图命名。

## 目录约定

每个规划文件夹内固定三样（缺哪样说明当时就没有）：

| 文件 | 含义 |
|---|---|
| `设计.md` | 设计书：问题、方案取舍、接口契约 |
| `实施计划.md` | 逐任务拆解的实施计划 |
| `执行记录/` | 执行期产物：任务 brief、report、review、diff |

## 归档时的去重结论

归档前这些文档散落在 6 个位置：主仓、`.worktrees/supervisor-worker-subagents`、
`.claude/worktrees/terminal-open-file-4cdd1d`，以及三个 codex worktree
（`daa3` / `ed71` / `05ea`）。共 271 个 md 文件，**规范化行尾后只有 115 份不同内容**。

去重依据是**内容哈希**（`tr -d '\r'` 规范化后取 md5），不是文件名：

1. **所有 plans 与 specs 在 6 个位置完全一致**，此前的差异全部只是 CRLF/LF
   行尾——按字节比较会误判成 14 处内容分歧。主仓版本为权威。

2. **`01-意图路由` 的执行记录来自 codex worktree `daa3`，不是主仓。**
   主仓 `.superpowers/sdd/` 用的是 `task-N-brief.md` 这类**通用文件名**，后续
   「分层用户记忆」那轮复用同名文件，把意图路由的 `task-1..6` 覆盖掉了，主仓
   只剩 `task-7..10`。`daa3` 保存着完整一轮（`task-1..10` + 6 份
   review-package），已逐字节确认 `task-7..10` 与主仓相同，故取 `daa3` 全套。

3. **`ed71` / `05ea` 两个 codex worktree 与两个 `.worktrees` 全部丢弃**——它们
   是同一轮执行的更早快照（`progress.md` 逐行核对为严格前缀），已被 `daa3`
   或主仓取代。

4. **`archive/` 与主仓 `.superpowers/sdd/` 顶层同名文件逐字节相同**
   （phase2 全部 8 份、graphrag、分层记忆全部 12 份），取 `archive/` 版本。

5. `phase2` 的 3 份 review diff 与 3 个生成脚本在工作区已被删除，从 git HEAD 取回。

6. `progress.md` 在 4 处各有一份，行数 8 / 24 / 59 / 59，**逐行核对为严格前缀关系**，
   取最全的 59 行版作为顶层 `执行总账.md`。同理 `ed71` 的 `task-4-report.md` 与
   `task-4-review-package.md` 是 `daa3` 版的严格前缀（`daa3` 追加了 PostgreSQL
   事务测试附录），丢弃。

**归档后校验**：把 6 处共 204 份文档逐一按内容哈希回查，未收录的 4 份全部是上述
已验证的严格前缀，无内容丢失。

顺带一提，`执行总账.md` 第 56 行当时就记下了这个坑：*"report file had a filename
collision with an unrelated earlier Task 5's report (task-brief/report files are named
by task number only, not per-plan)"*——正是第 2 条里主仓丢失 `task-1..6` 的成因。
本目录按规划分文件夹，就不会再有这个问题。

## 后续新增规划

新起一次规划就建 `NN-意图/`，编号接着往下排。原先 `docs/superpowers/{plans,specs}/`
不再使用（已 `git mv` 到此处，git 历史保留）。

> `.superpowers/sdd/` 仍是 superpowers 工作流的暂存目录（内含 `.gitignore` 为 `*`），
> 属于过程产物。一轮规划结束后把其中值得留的搬到对应 `NN-意图/执行记录/`。
